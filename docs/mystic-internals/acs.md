# ACS — evidence and remaining work

`src/lib/mystic/acs-candidate.ts` recognizes a conservative concatenated G/S List/Read ACS subset; it is **diagnostic-only**. One level-20 sandbox user matched 404 native selector areas; a count match is not authorization proof. `src/lib/auth/sandbox-messages.ts` still requires an explicit two-area allowlist and loopback development origin. `src/lib/auth/native-file-provider.ts` denies message-area authorization.

Linux ELF string evidence includes `listacs`, `readacs`, `postacs`, `sysopacs`, `acsnogroup`, and labels `List ACS`, `Read ACS`, `Post ACS`. These are **binary strings only**, not decoded evaluator semantics.

Research priorities: (1) trace ACS evaluator and verify G/S, concatenation, blank and `%` with addresses; (2) decode `groups_g.dat` Access/Hidden; (3) decode `mbases.dat` type/hidden flags and storage paths; (4) resolve exceptional area #1; (5) compare multiple accounts and denied areas; (6) distinguish List, Read and Post checks. Fail closed for unknown expressions, types or group rules. Never remove allowlist solely on a diagnostic match.
